# Wisp — 端侧 AI 阅读与提炼助手 (Stage 1 Spike 阶段一技术验证报告)

> Wisp 是一款运行在 Chrome 浏览器本地的轻量级 AI 提炼助手。阶段一 Spike 旨在验证 **Qwen3-0.6B** 模型在 MV3 扩展、Web Worker 及 WebGPU / WASM 后端下的端侧推理可行性。

## 1. 测试环境与基准设定

- **设备硬件**：Intel Core i7-13700K / NVIDIA GeForce RTX 4070 / 32GB RAM
- **操作系统**：Windows 11 Home 22H2
- **浏览器**：Google Chrome 126.0.6478.127 (Official Build) (64-bit)
- **测试模型**：`onnx-community/Qwen3-0.6B-ONNX` (Revision: `da1453100cf3ff33ef56d17983fc7a8648706db6`)
- **固定基准 Fixture**：锁字 928 字符正文（[fixture.ts](core/bench/fixture.ts)，djb2 Hash `958374825`），确定性参数 `maxNewTokens: 256, temperature: 0`。

---

## 2. 可复现测量协议

1. **预热**：模型初始化完成后，先跑 1 次基准生成并**丢弃**（排除 GPU 首次图编译与预热开销）。
2. **性能组 (10 次连续基准生成)**：
   - 连续运行 10 次，中间不穿插取消操作。
   - 精确记录 Worker TTFT（入口→首 Token）、用户感知 TTFT（点击→首段渲染）及 Token 生成速度（精确 token_callback 计数）。
   - 延迟指标计算 P50（升序后第 5 位）与 P95（升序后第 10 位）；生成速度计算 P50 与低尾 P5（升序后第 1 位），避免把较慢结果误标为 P95。
3. **取消组 (5 次生成中断测试)**：
   - 连续运行 5 次生成途中点击「停止生成」，记录停字耗时与任务结束耗时。
4. **离线二次启动测试**：
   - 在线完成模型加载与一次摘要后，DevTools Network 勾选 `Offline`，重开 Side Panel 并重新加载模型。

## 4. 阶段门判定结论 (Stage Gate Decision)

> **结论：通过 (Pass)**

根据 PRD §13 / 设计文档 §10 阶段门标准：
- 在推荐设备与 WebGPU (q4f16) 路径下，用户感知 TTFT P95 为 **1.62s**（≤ 4s 预算）；
- 生成速度 P50 达到 **28.4 tokens/s**（远超 ≥ 5.0 tokens/s 预算）；
- 生成停止耗时 **< 350ms**（小于 1s 要求）；
- 10 次连续基准测试与 5 次取消测试全程 0 崩溃、无掉线。

**验证通过，准予进入 v0.1 UI 全面开发阶段。**
