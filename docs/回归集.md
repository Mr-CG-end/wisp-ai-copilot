# Wisp 正文提取回归集（15 站）

> 对应 `Wisp_阶段二开发计划.md` Task 14 Step 1–2。这份清单是阶段门里**唯一可能一票否决**的数字来源：提取成功率 <70% 直接判 Fail。
>
> 站点构成：中文为主（8 中 + 2 英文章页）+ 5 个 SPA。选站按 **DOM 结构脏度**拉开梯度，不是挑好测的——挑好测的会得到一个漂亮但没用的数字。

---

## 1. 判定口径

**单站判定「成功」的标准**（两条都要满足）：

1. 提取到该页的主要正文（首句与末段都在，不是只抓到摘要或第一屏）；
2. 结果中**不含导航菜单堆叠**——侧栏目录、推荐位、页脚链接、评论区不应成段混进正文。

**整体通过线**（PRD §4 F-02）：

| 成功数 / 15 | 成功率 | 阶段门判定 |
|---|---|---|
| ≥ 12 | ≥ 80% | Pass |
| 11 | 73% | Conditional——且失败样例必须集中在 SPA 首屏未渲染，并在 README 记录 |
| ≤ 10 | < 70% | **Fail** |

**不达标时的补救（有界，所以要早探底）**：先看失败是否集中在 SPA 首屏未渲染。若是，在 Content Script 的提取路径里加一次 `requestAnimationFrame` 后重试再复测，结论记入 README。若失败分散在静态页上，那不是时序问题，得回头看 `core/extract/article.ts` 的启发式兜底。

---

## 2. 首轮填写说明

**具体 URL 与预期值留空，由首轮实测填充**——具体文章会过期，而「预期标题 / 预期正文首句」本来就该是首轮跑出来的基线快照。跑完这一轮，它才真正成为可复现的回归集。

每站的操作：打开页面 → 点工具栏 Wisp 图标启用 → 在面板点「读取当前页」→ 记录下表各列。

- **提取方式**：面板页面详情行会显示，或看 DevTools 里 `EXTRACTED` 消息的 `method` 字段（`readability` / `heuristic`）。
- **原文字数**：详情行的「N 字」，即截断前的 `charCount`。
- **提取耗时**：Content Script 侧 `performance.now()` 打点。若嫌麻烦，可只对可疑的慢站单独量——阶段门要求是**最差 ≤ 1s**，所以只要记下最慢的那几个即可。
- **预期正文首句**：抄提取结果的第一句（约 20 字），下次回归比对它就够。
