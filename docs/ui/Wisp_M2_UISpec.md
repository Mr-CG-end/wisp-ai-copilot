# Wisp M2 UI Spec

> 版本：v3.2（轨迹方向 + 设置页、错误分层与摘要可用性 gate）
> 范围：Side Panel + 划词工具条
> 适用界面：Chrome / Edge Side Panel，宽度 320～500px
> 规范来源：PRD v0.3、Design v0.2、阶段二开发计划 v0.1.2、轨迹 UI 设计方案（`docs/superpowers/specs/2026-07-27-wisp-thread-ui-design.md`）
>
> **v3 相对 v2 的实质变更**：装饰性微光轨迹升级为承载会话结构与六态的页面级信息骨架（新增 §5.9）；「快照」提升为有分量的视觉对象（§5.5 改写为快照凭证）；结果区从单一输出改为轮次列表（§5.7）；字号收敛为五档（§4.2）；`--wisp-text-muted` 加深至过 AA（§4.1）；新增划词工具条规范（§5.10），供 M3 Task 11 直接施工。
>
> **v3.1 相对 v3 的实质变更**：补齐审查报告（`docs/Wisp_审查报告_设计文档与UI.md`）§4 点名的两块规范空白——新增 §5.11 设置页规范（P-1 定稿：文字入口、App 内单层视图、行内两步确认），供 M3 Task 10 施工；新增 §5.12 错误呈现分层矩阵（P-3 定稿：四类分层与「整页态不得降级成横幅」禁令），与 `core/panel/errorCopy.ts` 一一对应。§5.6 增补一句限定 StatusBanner 只承载横幅层，§8 明确全面板只有一个 `aria-live` 区域。
>
> **v3.2 相对 v3.1 的实质变更**：整页摘要增加 `allow / warn / reject` 三态可用性 gate。活动流、碎片列表和正文不足不再进入模型；不确定材料需用户明确选择「仍然生成摘要」。本轮不新增列表概览任务。

## 1. 设计目标

Wisp 是在浏览器本地运行的离线 AI 阅读助手。界面需要让第一次使用的用户在不阅读说明文档的情况下完成：

1. 理解模型来源、下载体积和本地处理边界。
2. 主动确认后下载并初始化模型。
3. 读取当前网页，生成摘要并基于已读取内容追问。
4. 清楚判断任务状态、内容来源以及下一步操作。

设计关键词：编辑感、轻盈、可信、本地、精确、可展示。避免 AI 紫色、霓虹、玻璃拟态、渐变文字、过量卡片和装饰性动画。

v2 将“真实产品界面”和“作品集展示图”分开：Side Panel 保持浏览器工具的真实密度；展示图可以放入浏览器上下文和品牌说明，但不得改变产品 UI 本身。

## 2. 产品语义

- 用户主动启用页面后才读取正文。
- 正文只在 `readPage()` 时读取一次，之后使用内存快照；界面不得暗示持续监视网页。
- 只要存在页面快照，来源标识必须常驻。
- 切换标签页不自动混入新页面内容；提供明确的“改读当前页”操作。
- 未经用户点击“开始下载”，不得下载模型。
- 除模型文件下载外，网页正文、问题和回答均不上传。
- WebGPU 失败不得自动切换 WASM，必须由用户选择。
- 整页摘要在调用模型前必须经过 `allow / warn / reject` 三态 gate；拒绝是对材料形态的诚实说明，不是生成错误，也不产出猜测性的「页面概览」。

## 3. 画布与布局

### 3.1 基准画布

- 设计基准宽度：400px。
- 支持范围：320～500px。
- 页面背景填满 Side Panel，不使用居中的“手机外壳”或设备模型。
- 最小水平内边距：320px 时 14px；360px 及以上 16px。
- 内容最大宽度：468px，宽于该值时水平居中。
- 顶部工具栏高度：44px；主体纵向间距：16px。
- 页面按桌面工具密度设计，不使用触屏式超大控件和全屏 onboarding 留白。

### 3.2 页面骨架

1. 顶部工具栏：品牌字标、当前本地运行状态、轻量操作。
2. 快照凭证行（常驻）+ 页面详情行（可滚走）：首字母凭证、读取时刻、域名、标题、字数和重新读取。
3. 命令区：摘要等高频动作使用紧凑按钮；**首轮产生后主按钮降级为次级样式**，视觉重心让给结果。
4. 轮次列表：每轮一个轨道单元加一张纸面，历史与当前轮同构。
5. 底部提问栏：问题输入与发送操作，内容滚动时保持可用。
6. 状态区：错误、空、取消、跨标签提示，紧邻受影响内容。

不使用底部导航。M2 不展示设置、历史、划词工具条或阶段三功能入口。

## 4. 视觉令牌

### 4.1 颜色

| Token | 值 | 用途 |
|---|---|---|
| `--wisp-bg` | `#F2EFE7` | 暖象牙纸感背景 |
| `--wisp-surface` | `#FBFAF6` | 编辑器纸面 |
| `--wisp-surface-muted` | `#E9ECE5` | 次级状态、轻提示 |
| `--wisp-text` | `#20241F` | 深墨主文字，避免纯黑 |
| `--wisp-text-muted` | `#5F675E` | 元信息与辅助说明。v2 的 `#697168` 对 `--wisp-bg` 只有 4.39:1，未过 WCAG AA，v3 加深至此值 |
| `--wisp-border` | `#D7D6CE` | 分隔线和输入边框 |
| `--wisp-accent` | `#476C5A` | 唯一苔绿品牌强调色 |
| `--wisp-accent-hover` | `#395B4A` | 主按钮悬停 |
| `--wisp-accent-soft` | `#DCE8DF` | 选中态和成功提示 |
| `--wisp-danger` | `#B44B4B` | 危险操作与错误 |
| `--wisp-danger-soft` | `#F8E9E7` | 错误横幅背景 |
| `--wisp-warning` | `#946221` | 警告文字 |
| `--wisp-warning-soft` | `#F5EEDF` | 警告横幅背景 |
| `--wisp-focus` | `#1A73E8` | 键盘焦点环 |

页面只使用一个品牌强调色。错误和警告颜色仅用于语义状态，不用于装饰。

### 4.2 字体

使用系统字体，不加载远程字体：

```css
font-family: ui-sans-serif, system-ui, -apple-system, "Segoe UI", "Microsoft YaHei", sans-serif;
```

**字号收敛为五档：20 / 15 / 14 / 12 / 11px。** 10px、13px、16px、24px 一律不再使用。品牌字标的 18px 是唯一例外，它是字标不进文字层级。

| 层级 | 字号 / 行高 | 字重 |
|---|---|---|
| 页面标题 | 20px / 28px | 650 |
| 区块标题 | 15px / 22px | 600 |
| 正文 · 按钮 · 输入 | 14px / 22px | 400（按钮 600） |
| 元信息 | 12px / 18px | 450 |
| 微文本（轨道编号、凭证时刻、状态短语） | 11px / 16px | 500 |
| 品牌字标（不进层级） | 18px / 24px | 650 |

数字一律启用 `font-variant-numeric: tabular-nums`：轨道编号、快照时刻、页面字数、下载进度。等宽之外不再单设「数字进度」层级。

正文一行不超过约 52 个中文字符。模型输出段落之间保留 12px 间距，标题上下 20px / 8px。

### 4.3 间距与形状

- 基础网格：4px。
- 常用间距：4 / 8 / 12 / 16 / 20 / 24 / 32px。
- 输入框、按钮圆角：7px。
- 状态横幅圆角：8px。
- 编辑器纸面圆角：10px；其他区域优先使用分隔线和留白。
- 阴影仅用于悬浮提问栏或弹层：`0 10px 28px rgba(42, 53, 45, 0.09)`。
- 边框统一 1px。
- 品牌“微光轨迹”在 v3 升级为页面级信息骨架，规范移至 §5.9。它不再是「只能出现在上下文栏与编辑器边注之间」的装饰曲线，而是从快照凭证一路贯穿到每一轮输出的 1px 苔绿轨道。初始化页的四步引导线是同一语汇的另一处应用，不是另一种图形。

## 5. 组件规范

### 5.1 顶部工具栏

- 左侧显示 `Wisp`。
- 右侧显示小型状态文本：`本地 · WebGPU`，前置 5px 实心状态点。
- 状态点使用 `--wisp-accent`，不得发光或持续闪烁。
- 工具栏下方使用 1px 分隔线，不做独立卡片。
- 品牌字标采用紧凑字距和较高字重，不放置大号 App 标题。

### 5.2 按钮

- 高度 32～36px；仅初始化下载等关键确认按钮允许 40px。
- 主按钮：强调色实底、白字，默认按内容宽度，不自动铺满整行。
- 次按钮：白底、边框、主文字。
- 危险按钮：默认保持克制，仅文字或浅红底；确认危险操作时才使用红色实底。
- 按下反馈：`transform: translateY(1px)`，持续不超过 120ms。
- 禁用态必须同时降低对比度并改变鼠标状态，不能只依赖颜色。
- 焦点态固定 2px 蓝色外框，偏移 2px。

### 5.3 输入框

- 标签位于输入框上方。
- 高度至少 36px；底部问答编辑栏允许自适应到 72px。
- 默认白底、1px 边框；聚焦时边框变为强调色并显示焦点环。
- 占位文本：`基于本页内容提问…`。

### 5.4 进度条

- 高度 8px，轨道为 `--wisp-surface-muted`，进度为 `--wisp-accent`。
- 不使用循环动画；真实进度单调增长。
- 上方显示阶段标题，下方显示百分比和体积；收到下载回调后优先展示真实字节，不再按百分比反推体积。
- 示例：`38% · 217 MB / 570 MB`。首次回调前才使用 `ModelSetup.tsx` 的体积常量占位（WebGPU 570 MB、兼容模式 618 MB）。
- 用户点击下载后依次显示 `正在连接下载源…`、`正在测速…`、实时速度与预计剩余时间。15 秒没有新增字节时显示非阻断的慢连接提示，恢复传输后立即隐藏。
- 权重字节接收完成后，进度区改为 `下载完成，正在加载模型并进行自检…`；在自检通过并写入完整缓存清单之前，不得把模型标记为可用。

### 5.5 浏览器上下文栏（v3：快照凭证 + 详情行）

上下文栏拆成**两行独立元素**，因为二者的生命周期不同：凭证是全程需要的归属证明，标题与字数是一次性信息。

**常驻凭证行**（`sticky`，位于顶栏之下）

- 30px 圆角方块，内容是**域名首字母大写**，下方一行相对读取时刻（`刚刚读取` / `3 分钟前读取`）。
- **不发起任何网络请求获取真实 favicon** —— 这会突破「除模型下载外不出网」的红线。首字母是有意的设计选择，不是降级方案。
- 域名显示在右列，单行省略。
- 快照过期（绑定页已导航或刷新）时凭证转虚线描边、文案改为 `快照已过期`。
- 只 sticky 这一行：顶部固定占用 78px（顶栏 44 + 凭证行 34）。整条上下文栏 sticky 要占 132px，在矮窗口里比例过高。

**可滚走详情行**

- 页面标题（最多两行截断）、字数、提取范围、`重新读取`。
- 示例：`3,842 字 · 已读取前 3,000 字 · 重新读取`。

两行共用 §5.9 的 44px 轨道栅格：凭证与轨道同列，形成从页面源头贯穿到每一轮输出的连续视觉线。**不再显示写死的 `刚刚读取`**，时刻由真实读取时间戳算出，每 30s 刷新。

### 5.6 状态横幅

- 横幅与相关内容相邻，不固定在顶部。
- 结构：状态标题、可执行说明、可选操作按钮。
- 错误和警告使用浅色背景与左侧 3px 语义色边线，不使用大面积纯红或纯黄。
- 技术详情默认折叠，设计图不展开。
- **横幅只承载 §5.12 的 `banner` 层**。整页态用主内容区、单轮失败用轮次纸面，都不走横幅——错误码到层级的归位以 §5.12 的矩阵为准。

### 5.7 结果区：轮次列表（v3）

结果区不再是「一块输出 + 上方一段历史」，而是**一条轮次列表**。历史不是另一种东西，只是轨道上更早的节点，两者共用同一个组件。

- **一轮 = 轨道单元 + 纸面**。轨道宽 44px（320px 档 28px），纸面用 `--wisp-surface`、1px 边框、10px 圆角，是页面中唯一允许形成明显容器的区域。
- 轨道单元含线段、节点、两位数编号（`01`、`02`）与任务标签；标签在 320px 档隐去，只留编号。
- 纸面内部自上而下：来源行（仅当该轮来源与当前快照不同时出现）→ 工具行 → 正文。
- **操作栏位于纸面顶部工具行**，不在输出下方。理由：长输出流式滚动时，「停止」必须无需下拉即可点到；v2 的「输出下方」在短输出时成立，长输出时反而劣化。
- 工具行左侧显示状态短语（成功时显示来源标题），右侧生成中只有「停止」，完成后是「复制」「重新生成」。
- Markdown 标题、段落、列表和代码块保持清楚层级，标题统一 15px。
- **不使用流式插入光标** —— 生成中的状态由轨道节点形态（空心 + 线段生长）与工具行的 `生成中…` 共同表达，比一个闪烁方块更明确，也不必每帧重排。

**整页摘要可用性 gate**

gate 只约束整页摘要，不影响基于快照的具体问答和用户主动触发的划词总结。它是生成前的材料判断，不占用轨迹编号：`warn` 尚未开始生成，`reject` 也不是失败轮次。

| 判定 | 原因 | 命令区行为 | 后续链路 |
|---|---|---|---|
| `allow` | 材料足以支持连续正文摘要 | 正常显示「生成摘要」 | 点击后直接生成 |
| `warn` | `possibly_fragmented` | 在命令区就地提示「读取到的内容可能较零散，摘要可能不完整」；主操作改为「仍然生成摘要」，保留「重新读取」 | 只有用户明确继续后才调用模型 |
| `reject` | `activity_feed` / `fragmented_content` / `insufficient_content` | 用中性说明替换摘要主操作，不用红色、不显示「重试」 | 不调用模型、不创建任务、不写入会话 |

`reject` 推荐文案：`这页更像活动记录或导航列表，缺少可确认的连续正文。为避免把无关条目拼成结论，Wisp 没有生成摘要。可以划选一段内容总结，或打开具体提交 / PR 页面后再试。` 原因不是活动流时，首句按「内容较零散」或「可用正文太少」替换。不得把拒绝包装成空结果，也不得在本轮自动生成列表概览。

### 5.8 底部提问栏

- 固定在可视区域底部，使用纸面背景、1px 边框和轻量阴影。
- 输入占据主要宽度，发送使用 32px 方形箭头按钮并提供 `aria-label="发送问题"`。
- 占位文本：`基于这份快照提问…`。
- 不模拟移动聊天 App：不使用圆形头像、气泡对话或巨大的胶囊输入框。

### 5.9 轨迹

轨迹是页面级信息骨架，不是装饰。它替代 v2 §4.3 那条「只能出现在上下文栏与编辑器边注之间」的微光曲线。

- **线即分隔线**：1px 苔绿线位于 44px 轨道的右缘，同时承担轨道与内容的分隔职责，不再额外画边框。
- **逐轮画段**：每一轮自己画一段线，段与段首尾相接形成连续轨迹；不用一条贯穿全页的绝对定位长线，否则轮次高度变化时会错位。
- **节点骑在线上**，`top` 对齐纸面工具行。

五种状态的形态必须**静态可区分**（不能只靠动画区分，`prefers-reduced-motion` 下动画会被跳过）：

| 状态 | 节点 | 线段 |
|---|---|---|
| 生成中 | 实线描边、空心 | 苔绿，首次出现时向下生长 900ms |
| 成功 | 实心苔绿 | 苔绿实线 |
| 空结果 | **虚线**描边、空心 | 苔绿实线 |
| 已停止 | 实心 + 横杠断口 | 苔绿虚线 |
| 出错 | 实心暖红 | 暖红实线 |

**红线**：

- 轨迹图形整体 `aria-hidden="true"`。它是状态的视觉加速器，状态本身必须同时由文字承载（轮次容器的 `aria-label` + 纸面内的状态短语）。读屏用户不必去理解一条线。
- 动效一律用 CSS transition／transform，禁止逐帧 JS 动画。`prefers-reduced-motion: reduce` 下跳终态。
- 单一强调色，不引入第二强调色、渐变或玻璃拟态。

**初始化页复用同一套节点语汇**表达四步（确认模型来源 → 下载权重／缓存命中 → 加载到后端 → 自检一次生成），让首次约 47 秒的等待变得可理解。

### 5.10 划词工具条（供 M3 Task 11 施工）

- **首次发现采用双层提示，不做常驻悬浮球。** Side Panel 在「无页面快照且无轮次」的空状态里，长期显示「也可以直接划词」及四动作静态示意；它只解释入口，不复制一套可点击按钮。
- 当前页成功注入 Content Script 后，若用户尚未实际点击过划词动作，在视口底部居中显示一次「Wisp 划词已启用 / 选中文字即可解释、总结、改写或翻译」，4 秒后自动消失。提示不锁定选区，用户开始划词时由真实工具条立即替换。
- 首次点击有效划词动作后写入独立 UI 引导标记，后续页面不再主动提示；清除会话或模型不重置，只有「清除全部数据」重置。提示失败不得影响注入、面板打开或划词主链路。
- 高 34px，8px 圆角，`--wisp-surface` 底，比面板深一档的 1px 边框，投影 `0 4px 16px rgba(0, 0, 0, 0.16)`。
- 左侧 3px 苔绿边条，与面板的品牌语汇一致。
- 四个动作（解释 / 总结 / 改写 / 翻译）**用文字不用图标** —— 图标在 34px 高度里既难辨认又需要额外的可访问名。
- 点击后**就地**显示「正在解释…」并向右生长一条 1px 苔绿线，约 1.5s 后消失。工具条不等结果，结果在 Side Panel 里出。
- `role="toolbar"`，Esc 关闭，Tab 在四个动作间循环。
- **不做背景自适应**：深色网页上自动反色会让苔绿消失，品牌识别度比在个别页面上的融合度更重要。工具条始终是浅色纸面。
- 首次启用提示复用同一 Shadow DOM 纸面，只以 `opacity` 与 `transform` 入场；`prefers-reduced-motion: reduce` 下无入场动画。它固定在视口内，不改变 `body.scrollHeight`，不产生新滚动条。

### 5.11 设置页（供 M3 Task 10 施工）

设置页承载五组内容：模型后端 / 保留时长 / 数据用量 / 清除数据 / 隐私说明。M2 界面不出现设置入口（§3.2、§9），本节是 M3 的施工依据。

> **没有「输出长度」这一组。** 它已被裁撤，输出上限完全由性能档位按实测速度自动决定（设计文档 §2.2「保留两套并存只会产生『用户选了 long 但档位把它压回 256』这类无法解释的行为」）。当前档位已在顶栏常驻显示（审查报告 P-4），设置页不重复呈现，也不提供手动覆盖。

**入口**

- 顶栏右侧、运行状态之后，**文字按钮**「设置」，不用图标。理由有二：§8 要求所有按钮有可见文本，图标要额外配可访问名；且 v0.1 尚无图标资产（审查报告 P-8），文字按钮不引入这项依赖。
- 按钮用 §5.2 的次按钮尺寸下限（32px），字号与顶栏状态文本同档，不抢品牌字标的视觉重心。

**导航：App 内单层视图切换**

- 点击「设置」在**同一个 Side Panel 内**切换到设置视图，顶栏左侧的品牌字标位置变为「返回」文字按钮，返回即回到任务视图的原有状态（不重置滚动位置以外的任何状态）。
- **不使用 `options_page`**。options 页会把用户从 400px 面板弹到全屏新标签页，而设置页最关键的动线是「清除数据 → 回面板确认结果」——跨标签页会直接把这条动线切断，用户无法在原地看到清除生效。
- 不引入底部导航、不做多级设置树。五组内容在一屏内纵向排列，超出即普通滚动。

**内容呈现**

- 全部复用既有 `.wisp-meta-list` 行样式：左侧标签、右侧值或控件，行间 1px 分隔线，不给每组套卡片。
- 存储用量是**一行文本**：`约 412 MB · 会话 3 条 · 缓存 12 项`。不做图表、进度环或仪表盘——这是一个数值，不是一份报告。
- 「保留时长」行：7 天（默认）/ 不保留（关闭标签页即清除）。两个取值对应 `Settings.retentionDays` 的 `7 | 0`，没有第三档——更细的粒度需要一整套过期策略界面，不属 v0.1。
- 「模型后端」行：自动（默认）/ WebGPU / 兼容模式。语义是**首选后端而非立即切换**：两个后端用的是不同量化文件，改选项不触发任何下载，只在与当前运行后端不一致时显示提示与「重新加载模型」。兼容模式下必须写明两句——不占用显卡因而网页浏览更流畅；与 WebGPU 用不同的量化文件，切换后需另外下载。缺第二句会让一次点击触发一场巨型下载。
- 隐私说明是静态文本段，不外链、不折叠。

**清除数据：行内两步确认**

- 第一步：危险按钮按 §5.2 的克制态呈现（文字或浅红底）。
- 第二步：点击后按钮**原位**变为红色实底「确认清除」，右侧出现文字按钮「取消」。这正是 §5.2「确认危险操作时才使用红色实底」预留的状态。
- **5 秒内未确认自动还原**为第一步形态，不弹模态对话框。400px 面板里模态要覆盖整屏，代价远大于一次原位确认；自动还原保证误触不会留下一个持续危险的按钮。
- 清除完成后，数据用量行就地更新为新数值，并由状态行播报一次（§8）。

**隐身指示**

- 隐身窗口下，顶栏运行状态追加灰字第三段「隐身 · 不保存」。
- 设置页的数据用量组显示一行说明：本次会话不写入本地库，关闭窗口即消失。

**明文决策：v0.1 不提供会话历史浏览界面**

库内数据只通过「数据用量」的计数可见、通过「清除数据」可控。写进规范是因为：历史入口在 M3 途中极容易被临时加出来，而它会连带出检索、命名、导出、单条删除一整串未定范围的界面。

### 5.12 错误呈现分层矩阵

错误按**影响面**分四层，不按严重程度。文案与分层的唯一数据源是 `core/panel/errorCopy.ts`（`ERROR_COPY`），界面只读它，不在组件里另写一份字符串。

| 层级 | 视觉承载 | tone | 错误码 |
|---|---|---|---|
| `page` 整页态 | 替换主内容区，沿用 ModelSetup 骨架：标题 + 说明 + 主操作按钮 | 中性纸面，不铺红底 | `WEBGPU_UNAVAILABLE`、`OFFLINE_NO_MODEL`、`CACHE_CORRUPT`、`DOWNLOAD_FAILED`、`STORAGE_FULL` |
| `banner` 页面横幅 | 紧邻上下文栏下方的状态横幅（§5.6），StatusBanner 的唯一职责 | 浅色底 + 左侧 3px 语义色边线 | `PAGE_PERMISSION_REQUIRED`、`PAGE_INJECTION_BLOCKED`、`PAGE_NO_CONTENT`、`TAB_CHANGED` |
| `turn` 轮次内 | 该轮纸面内的 `.wisp-state-error`，轨道节点转暖红实心（§5.9），已有输出保留 | 暖红节点 + 纸面内说明 | `WORKER_ERROR`、`WEBGPU_CRASH`，以及 empty / cancelled 两个非错误终态 |
| `inline` 行内 | 跟在相关信息旁的小字，沿用 truncated-note 样式 | 仅 `--wisp-text-muted`，无边线无底色 | `PAGE_TOO_LONG`、`DOWNLOAD_CANCELLED`、`FILL_FAILED`（v0.2 F-04 预留） |

- 每层的标题字号固定，`retryable` 为真时按钮位置固定（整页态在说明下方，横幅在右侧，轮次内在工具行），技术详情一律 `<details>` 折叠。
- **禁令：整页态不得降级成横幅。** 这五个码意味着模型不可用，不解决就什么也做不了；压成一条可滚走的小横幅会让用户在一个看似正常的界面里反复点击无效按钮。「统一走 StatusBanner」指的是横幅层内部统一，不是把四层压成一层。
- 文案红线：全表任何文案不得暗示 Wisp 在持续读取或监视页面（快照语义，见阶段二计划 §2）。`errorCopy.test.ts` 对全表做字符串断言，禁止「仍在」「持续读取」「实时」「监视」。

**两条产品口径**（后续工作包照此实现）

1. **划词动作抢占在途生成时不弹确认框。** 用户在页面上划词点动作，是一个明确的新意图；弹确认框会直接顶掉「从点击工具条到 Side Panel 显示任务状态 ≤ 500ms」的验收指标。被抢占的那一轮不会丢失——它以「已停止」轮次留在轨迹上（§5.9 的停止态：实心节点 + 横杠断口 + 虚线段），已生成的内容原样保留在纸面里。
2. **面板只保留一个 `aria-live` 区域**，挂在状态行上（§8）。新增横幅若用 `role="status"`，必须先确认它与状态行不会播报同一件事——同一个错误被读两遍比不读更糟。横幅与状态行同时出现同一状态时，横幅退化为静态文本（无 `role`），由状态行统一播报。

## 7. 响应式规则

- **320px（`max-width: 359px`）**：水平内边距 14px；按钮组可纵向堆叠；上下文标题最多两行；**轨道收窄至 28px（栅格间距 8px），轨道内只留编号，任务标签隐去**，纸面左外边距 8px。
- **360～419px**：默认布局，轨道 44px、栅格间距 12px。
- **420～500px**：水平内边距保持 16px；**轨道不增宽，多出的宽度全部给正文** —— 轨道已占 44px，正文行宽是本设计的稀缺资源。
- 不出现横向滚动。
- 长标题使用两行截断；完整标题可通过原生 `title` 或可访问名称获得。

## 8. 状态与无障碍

- M2 异步功能覆盖 `idle / loading / success / empty / error / cancelled`。
- 所有按钮使用可见文字；仅装饰图形不进入无障碍树。
- **`aria-live="polite"` 只挂状态行，不得挂正文容器，且全面板只有这一个播报区域**。流式正文每 60～120ms flush 一次，挂在正文上会让读屏每秒播报十余次，是实打实的可用性缺陷。正文完成时由状态行用 `role="status"` 播报一次即可；新增横幅要按 §5.12 的口径避免重复播报。
- 键盘 Tab 顺序必须与视觉顺序一致。
- `prefers-reduced-motion: reduce` 下禁用动画与过渡。
- 文本和背景达到 WCAG AA 对比度。
- 不仅用颜色表达成功、警告或错误。

## 9. 设计与实现验收

- 设计图必须像可直接实现的产品界面，不使用设备外壳、透视展示或概念艺术背景。
- 作品集展示板可使用浏览器上下文和编辑网格，但其中的 Side Panel 必须与产品方向图一致。
- 判定“像浏览器扩展”而不是“像移动 App”：控件紧凑、页面上下文明确、没有大面积 onboarding 留白和触屏式按钮。
- 图片中的小字若与本规范冲突，以本规范为准。
- 实现时只使用普通 CSS，不引入 Tailwind、远程字体、动画库或 UI 组件库。
- 通过 320px、360px、500px 三种宽度截图与设计图比对。
- M2 实现不得提前加入设置页、会话历史、划词工具条或阶段三入口。
