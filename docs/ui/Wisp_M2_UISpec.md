# Wisp M2 UI Spec

> 版本：v3.0（轨迹方向）
> 范围：Side Panel + 划词工具条
> 适用界面：Chrome / Edge Side Panel，宽度 320～500px
> 规范来源：PRD v0.3、Design v0.2、阶段二开发计划 v0.1.2、轨迹 UI 设计方案（`docs/superpowers/specs/2026-07-27-wisp-thread-ui-design.md`）
>
> **v3 相对 v2 的实质变更**：装饰性微光轨迹升级为承载会话结构与六态的页面级信息骨架（新增 §5.9）；「快照」提升为有分量的视觉对象（§5.5 改写为快照凭证）；结果区从单一输出改为轮次列表（§5.7）；字号收敛为五档（§4.2）；`--wisp-text-muted` 加深至过 AA（§4.1）；新增划词工具条规范（§5.10），供 M3 Task 11 直接施工。

## 1. 设计目标

Wisp 是在浏览器本地运行的离线 AI 阅读助手。界面需要让第一次使用的用户在不阅读说明文档的情况下完成：

1. 理解模型来源、下载体积和本地处理边界。
2. 主动确认后下载并初始化模型。
3. 读取当前网页，生成摘要并基于已读取内容追问。
4. 清楚判断任务状态、内容来源以及下一步操作。

设计关键词：编辑感、轻盈、可信、本地、精确、可展示。避免 AI 紫色、霓虹、玻璃拟态、渐变文字、过量卡片和装饰性动画。

v2 将“真实产品界面”和“作品集展示图”分开：Side Panel 保持浏览器工具的真实密度；展示图可以放入浏览器上下文和品牌说明，但不得改变产品 UI 本身。

## 2. 产品语义

- 用户主动启用页面后才读取正文。
- 正文只在 `readPage()` 时读取一次，之后使用内存快照；界面不得暗示持续监视网页。
- 只要存在页面快照，来源标识必须常驻。
- 切换标签页不自动混入新页面内容；提供明确的“改读当前页”操作。
- 未经用户点击“开始下载”，不得下载模型。
- 除模型文件下载外，网页正文、问题和回答均不上传。
- WebGPU 失败不得自动切换 WASM，必须由用户选择。

## 3. 画布与布局

### 3.1 基准画布

- 设计基准宽度：400px。
- 支持范围：320～500px。
- 页面背景填满 Side Panel，不使用居中的“手机外壳”或设备模型。
- 最小水平内边距：320px 时 14px；360px 及以上 16px。
- 内容最大宽度：468px，宽于该值时水平居中。
- 顶部工具栏高度：44px；主体纵向间距：16px。
- 页面按桌面工具密度设计，不使用触屏式超大控件和全屏 onboarding 留白。

### 3.2 页面骨架

1. 顶部工具栏：品牌字标、当前本地运行状态、轻量操作。
2. 快照凭证行（常驻）+ 页面详情行（可滚走）：首字母凭证、读取时刻、域名、标题、字数和重新读取。
3. 命令区：摘要等高频动作使用紧凑按钮；**首轮产生后主按钮降级为次级样式**，视觉重心让给结果。
4. 轮次列表：每轮一个轨道单元加一张纸面，历史与当前轮同构。
5. 底部提问栏：问题输入与发送操作，内容滚动时保持可用。
6. 状态区：错误、空、取消、跨标签提示，紧邻受影响内容。

不使用底部导航。M2 不展示设置、历史、划词工具条或阶段三功能入口。

## 4. 视觉令牌

### 4.1 颜色

| Token | 值 | 用途 |
|---|---|---|
| `--wisp-bg` | `#F2EFE7` | 暖象牙纸感背景 |
| `--wisp-surface` | `#FBFAF6` | 编辑器纸面 |
| `--wisp-surface-muted` | `#E9ECE5` | 次级状态、轻提示 |
| `--wisp-text` | `#20241F` | 深墨主文字，避免纯黑 |
| `--wisp-text-muted` | `#5F675E` | 元信息与辅助说明。v2 的 `#697168` 对 `--wisp-bg` 只有 4.39:1，未过 WCAG AA，v3 加深至此值 |
| `--wisp-border` | `#D7D6CE` | 分隔线和输入边框 |
| `--wisp-accent` | `#476C5A` | 唯一苔绿品牌强调色 |
| `--wisp-accent-hover` | `#395B4A` | 主按钮悬停 |
| `--wisp-accent-soft` | `#DCE8DF` | 选中态和成功提示 |
| `--wisp-danger` | `#B44B4B` | 危险操作与错误 |
| `--wisp-danger-soft` | `#F8E9E7` | 错误横幅背景 |
| `--wisp-warning` | `#946221` | 警告文字 |
| `--wisp-warning-soft` | `#F5EEDF` | 警告横幅背景 |
| `--wisp-focus` | `#1A73E8` | 键盘焦点环 |

页面只使用一个品牌强调色。错误和警告颜色仅用于语义状态，不用于装饰。

### 4.2 字体

使用系统字体，不加载远程字体：

```css
font-family: ui-sans-serif, system-ui, -apple-system, "Segoe UI", "Microsoft YaHei", sans-serif;
```

**字号收敛为五档：20 / 15 / 14 / 12 / 11px。** 10px、13px、16px、24px 一律不再使用。品牌字标的 18px 是唯一例外，它是字标不进文字层级。

| 层级 | 字号 / 行高 | 字重 |
|---|---|---|
| 页面标题 | 20px / 28px | 650 |
| 区块标题 | 15px / 22px | 600 |
| 正文 · 按钮 · 输入 | 14px / 22px | 400（按钮 600） |
| 元信息 | 12px / 18px | 450 |
| 微文本（轨道编号、凭证时刻、状态短语） | 11px / 16px | 500 |
| 品牌字标（不进层级） | 18px / 24px | 650 |

数字一律启用 `font-variant-numeric: tabular-nums`：轨道编号、快照时刻、页面字数、下载进度。等宽之外不再单设「数字进度」层级。

正文一行不超过约 52 个中文字符。模型输出段落之间保留 12px 间距，标题上下 20px / 8px。

### 4.3 间距与形状

- 基础网格：4px。
- 常用间距：4 / 8 / 12 / 16 / 20 / 24 / 32px。
- 输入框、按钮圆角：7px。
- 状态横幅圆角：8px。
- 编辑器纸面圆角：10px；其他区域优先使用分隔线和留白。
- 阴影仅用于悬浮提问栏或弹层：`0 10px 28px rgba(42, 53, 45, 0.09)`。
- 边框统一 1px。
- 品牌“微光轨迹”在 v3 升级为页面级信息骨架，规范移至 §5.9。它不再是「只能出现在上下文栏与编辑器边注之间」的装饰曲线，而是从快照凭证一路贯穿到每一轮输出的 1px 苔绿轨道。初始化页的四步引导线是同一语汇的另一处应用，不是另一种图形。

## 5. 组件规范

### 5.1 顶部工具栏

- 左侧显示 `Wisp`。
- 右侧显示小型状态文本：`本地 · WebGPU`，前置 5px 实心状态点。
- 状态点使用 `--wisp-accent`，不得发光或持续闪烁。
- 工具栏下方使用 1px 分隔线，不做独立卡片。
- 品牌字标采用紧凑字距和较高字重，不放置大号 App 标题。

### 5.2 按钮

- 高度 32～36px；仅初始化下载等关键确认按钮允许 40px。
- 主按钮：强调色实底、白字，默认按内容宽度，不自动铺满整行。
- 次按钮：白底、边框、主文字。
- 危险按钮：默认保持克制，仅文字或浅红底；确认危险操作时才使用红色实底。
- 按下反馈：`transform: translateY(1px)`，持续不超过 120ms。
- 禁用态必须同时降低对比度并改变鼠标状态，不能只依赖颜色。
- 焦点态固定 2px 蓝色外框，偏移 2px。

### 5.3 输入框

- 标签位于输入框上方。
- 高度至少 36px；底部问答编辑栏允许自适应到 72px。
- 默认白底、1px 边框；聚焦时边框变为强调色并显示焦点环。
- 占位文本：`基于本页内容提问…`。

### 5.4 进度条

- 高度 8px，轨道为 `--wisp-surface-muted`，进度为 `--wisp-accent`。
- 不使用循环动画；真实进度单调增长。
- 上方显示阶段标题，下方显示百分比和体积。
- 示例：`38% · 约 217 MB / 570 MB`。体积以 `ModelSetup.tsx` 的 `MODEL_SIZE_MB` 为准（v0.1 由 390 更正为 570，原值少报约 46%，而「下载前如实告知体积」是产品红线之一）。

### 5.5 浏览器上下文栏（v3：快照凭证 + 详情行）

上下文栏拆成**两行独立元素**，因为二者的生命周期不同：凭证是全程需要的归属证明，标题与字数是一次性信息。

**常驻凭证行**（`sticky`，位于顶栏之下）

- 30px 圆角方块，内容是**域名首字母大写**，下方一行相对读取时刻（`刚刚读取` / `3 分钟前读取`）。
- **不发起任何网络请求获取真实 favicon** —— 这会突破「除模型下载外不出网」的红线。首字母是有意的设计选择，不是降级方案。
- 域名显示在右列，单行省略。
- 快照过期（绑定页已导航或刷新）时凭证转虚线描边、文案改为 `快照已过期`。
- 只 sticky 这一行：顶部固定占用 78px（顶栏 44 + 凭证行 34）。整条上下文栏 sticky 要占 132px，在矮窗口里比例过高。

**可滚走详情行**

- 页面标题（最多两行截断）、字数、提取范围、`重新读取`。
- 示例：`3,842 字 · 已读取前 3,000 字 · 重新读取`。

两行共用 §5.9 的 44px 轨道栅格：凭证与轨道同列，形成从页面源头贯穿到每一轮输出的连续视觉线。**不再显示写死的 `刚刚读取`**，时刻由真实读取时间戳算出，每 30s 刷新。

### 5.6 状态横幅

- 横幅与相关内容相邻，不固定在顶部。
- 结构：状态标题、可执行说明、可选操作按钮。
- 错误和警告使用浅色背景与左侧 3px 语义色边线，不使用大面积纯红或纯黄。
- 技术详情默认折叠，设计图不展开。

### 5.7 结果区：轮次列表（v3）

结果区不再是「一块输出 + 上方一段历史」，而是**一条轮次列表**。历史不是另一种东西，只是轨道上更早的节点，两者共用同一个组件。

- **一轮 = 轨道单元 + 纸面**。轨道宽 44px（320px 档 28px），纸面用 `--wisp-surface`、1px 边框、10px 圆角，是页面中唯一允许形成明显容器的区域。
- 轨道单元含线段、节点、两位数编号（`01`、`02`）与任务标签；标签在 320px 档隐去，只留编号。
- 纸面内部自上而下：来源行（仅当该轮来源与当前快照不同时出现）→ 工具行 → 正文。
- **操作栏位于纸面顶部工具行**，不在输出下方。理由：长输出流式滚动时，「停止」必须无需下拉即可点到；v2 的「输出下方」在短输出时成立，长输出时反而劣化。
- 工具行左侧显示状态短语（成功时显示来源标题），右侧生成中只有「停止」，完成后是「复制」「重新生成」。
- Markdown 标题、段落、列表和代码块保持清楚层级，标题统一 15px。
- **不使用流式插入光标** —— 生成中的状态由轨道节点形态（空心 + 线段生长）与工具行的 `生成中…` 共同表达，比一个闪烁方块更明确，也不必每帧重排。

### 5.8 底部提问栏

- 固定在可视区域底部，使用纸面背景、1px 边框和轻量阴影。
- 输入占据主要宽度，发送使用 32px 方形箭头按钮并提供 `aria-label="发送问题"`。
- 占位文本：`基于这份快照提问…`。
- 不模拟移动聊天 App：不使用圆形头像、气泡对话或巨大的胶囊输入框。

### 5.9 轨迹

轨迹是页面级信息骨架，不是装饰。它替代 v2 §4.3 那条「只能出现在上下文栏与编辑器边注之间」的微光曲线。

- **线即分隔线**：1px 苔绿线位于 44px 轨道的右缘，同时承担轨道与内容的分隔职责，不再额外画边框。
- **逐轮画段**：每一轮自己画一段线，段与段首尾相接形成连续轨迹；不用一条贯穿全页的绝对定位长线，否则轮次高度变化时会错位。
- **节点骑在线上**，`top` 对齐纸面工具行。

五种状态的形态必须**静态可区分**（不能只靠动画区分，`prefers-reduced-motion` 下动画会被跳过）：

| 状态 | 节点 | 线段 |
|---|---|---|
| 生成中 | 实线描边、空心 | 苔绿，首次出现时向下生长 900ms |
| 成功 | 实心苔绿 | 苔绿实线 |
| 空结果 | **虚线**描边、空心 | 苔绿实线 |
| 已停止 | 实心 + 横杠断口 | 苔绿虚线 |
| 出错 | 实心暖红 | 暖红实线 |

**红线**：

- 轨迹图形整体 `aria-hidden="true"`。它是状态的视觉加速器，状态本身必须同时由文字承载（轮次容器的 `aria-label` + 纸面内的状态短语）。读屏用户不必去理解一条线。
- 动效一律用 CSS transition／transform，禁止逐帧 JS 动画。`prefers-reduced-motion: reduce` 下跳终态。
- 单一强调色，不引入第二强调色、渐变或玻璃拟态。

**初始化页复用同一套节点语汇**表达四步（确认模型来源 → 下载权重／缓存命中 → 加载到后端 → 自检一次生成），让首次约 47 秒的等待变得可理解。

### 5.10 划词工具条（供 M3 Task 11 施工）

- 高 34px，8px 圆角，`--wisp-surface` 底，比面板深一档的 1px 边框，投影 `0 4px 16px rgba(0, 0, 0, 0.16)`。
- 左侧 3px 苔绿边条，与面板的品牌语汇一致。
- 四个动作（解释 / 总结 / 改写 / 翻译）**用文字不用图标** —— 图标在 34px 高度里既难辨认又需要额外的可访问名。
- 点击后**就地**显示「正在解释…」并向右生长一条 1px 苔绿线，约 1.5s 后消失。工具条不等结果，结果在 Side Panel 里出。
- `role="toolbar"`，Esc 关闭，Tab 在四个动作间循环。
- **不做背景自适应**：深色网页上自动反色会让苔绿消失，品牌识别度比在个别页面上的融合度更重要。工具条始终是浅色纸面。

### 6.5 v2 任务工作区方向说明

第一轮 v2 方向验证图。单个 400px 真实 Side Panel，不使用展示外框。

必须包含：

- 44px 顶部工具栏：`Wisp`、`本地 · WebGPU`。
- 浏览器上下文栏：favicon、`web.dev · 刚刚读取`、文章标题、字数、快照范围、`重新读取`。
- 紧凑命令行：主操作 `生成摘要`，次操作 `复制页面链接` 不属于 M2，禁止出现。

## 7. 响应式规则

- **320px（`max-width: 359px`）**：水平内边距 14px；按钮组可纵向堆叠；上下文标题最多两行；**轨道收窄至 28px（栅格间距 8px），轨道内只留编号，任务标签隐去**，纸面左外边距 8px。
- **360～419px**：默认布局，轨道 44px、栅格间距 12px。
- **420～500px**：水平内边距保持 16px；**轨道不增宽，多出的宽度全部给正文** —— 轨道已占 44px，正文行宽是本设计的稀缺资源。
- 不出现横向滚动。
- 长标题使用两行截断；完整标题可通过原生 `title` 或可访问名称获得。

## 8. 状态与无障碍

- M2 异步功能覆盖 `idle / loading / success / empty / error / cancelled`。
- 所有按钮使用可见文字；仅装饰图形不进入无障碍树。
- **`aria-live="polite"` 只挂状态行，不得挂正文容器**。流式正文每 60～120ms flush 一次，挂在正文上会让读屏每秒播报十余次，是实打实的可用性缺陷。正文完成时由状态行用 `role="status"` 播报一次即可。
- 键盘 Tab 顺序必须与视觉顺序一致。
- `prefers-reduced-motion: reduce` 下禁用动画与过渡。
- 文本和背景达到 WCAG AA 对比度。
- 不仅用颜色表达成功、警告或错误。

## 9. 设计与实现验收

- 设计图必须像可直接实现的产品界面，不使用设备外壳、透视展示或概念艺术背景。
- 作品集展示板可使用浏览器上下文和编辑网格，但其中的 Side Panel 必须与产品方向图一致。
- 判定“像浏览器扩展”而不是“像移动 App”：控件紧凑、页面上下文明确、没有大面积 onboarding 留白和触屏式按钮。
- 图片中的小字若与本规范冲突，以本规范为准。
- 实现时只使用普通 CSS，不引入 Tailwind、远程字体、动画库或 UI 组件库。
- 通过 320px、360px、500px 三种宽度截图与设计图比对。
- M2 实现不得提前加入设置页、会话历史、划词工具条或阶段三入口。
