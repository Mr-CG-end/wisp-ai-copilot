# Wisp —— 需求文档（PRD v0.3 · 可执行版）

> **Wisp**（一缕微光）是一款住在浏览器里的离线 AI 副驾驶：小而轻，核心推理在本地完成，网页内容和用户文档不上传。

| 文档信息 | 内容 |
|---|---|
| 状态 | 草案，等待阶段一技术验证 |
| 产品形态 | Chrome / Edge 桌面扩展（Manifest V3） |
| 主要语言 | 中文 UI；支持处理中、英文网页内容 |
| 核心约束 | 零业务后端、零 API Key、本地推理、用户确认后才写入网页 |
| 开发方式 | 单人开发，使用 AI 辅助 |
| 计划周期 | 约 1 周；暂按 2026-07-21 至 2026-07-28 排期，具体投入小时数未确认 |
| 目标 | 完成一款可稳定演示、可提交 Chrome Web Store、适合作为求职作品集主项目的产品 |

---

## 0. 一句话电梯陈述

> 一个首次初始化后即可离线使用的浏览器 AI 副驾驶：在任意已授权网页上总结、解释和起草内容，并能检索本地文档、识别图片文字。除用户主动触发的模型下载外，网页内容、文档、图片、提示词和回答均不上传。

产品钩子：**本地隐私 + 浏览器原生体验 + 完整可用**。

“打开即用”在本文中特指：用户完成首次模型下载后，后续无需登录、API Key 或服务端，即可离线使用核心功能；不表示首次安装时无需初始化。

## 1. 产品目标与非目标

### 1.1 产品目标

1. 用户主动唤起 Wisp 后，可对当前网页进行总结和问答。
2. 用户选中文字后，可快速执行解释、总结、改写和翻译。
3. 用户可让 Wisp 生成输入框草稿，但必须确认后才写入，永不自动提交。
4. 用户可在本地导入文档并获得带可核对出处的回答。
5. 用户可从截图或图片中提取文字，并继续进行本地问答。
6. 核心功能在模型完成缓存后可离线运行；无遥测、无广告 SDK、无业务服务器。

### 1.2 非目标

- 不做联网搜索、实时事实核验或云模型回退。
- 不代替用户点击“发送”“发布”“购买”“支付”等按钮。
- 不读取或写入密码、验证码、支付、身份认证等敏感字段。
- 不做跨设备同步、账户系统或多人协作。
- 不承诺处理所有网站、跨域 iframe、Canvas 文本、复杂富文本编辑器和受浏览器保护的页面。
- 不承诺达到云端大模型的通用推理质量；优先做好摘要、解释、改写、检索和短草稿。
- v0.1 不追求 RAG、OCR 和模型切换；这些能力在技术可行性验证后进入后续版本。

## 2. 目标用户与核心场景

### 2.1 主要用户

优先服务在 Chrome / Edge 桌面端阅读中英文资料、重视隐私且不希望购买 API 的学生、开发者和知识工作者。

### 2.2 核心任务

1. **网页理解**：快速理解长文章、文档页和技术内容。
2. **划词处理**：对当前选区进行解释、总结、改写或中英互译。
3. **安全起草**：根据页面上下文生成短回复，由用户确认后填入指定输入框。
4. **本地检索**：对用户主动导入的 PDF 或保存的网页内容进行带出处问答。
5. **图片取字**：从用户主动选择的截图或图片中提取中英文文字。

### 2.3 首版支持边界

- 支持普通 HTML 文章页和常见 SPA 中可通过 DOM 读取的文本。
- 不支持 `chrome://`、Chrome Web Store、浏览器新标签页等禁止扩展注入的页面，并显示明确说明。
- 跨域 iframe、Canvas、视频字幕和虚拟滚动区域不保证完整提取。
- 网页内嵌 PDF 不作为“网页正文”处理；用户需通过“导入 PDF”进入文档流程。
- 用户必须先在当前页面主动打开或启用 Wisp，插件才读取该页内容。

## 3. 版本范围与优先级

### P0 / v0.1 —— 可独立演示的 MVP

- [ ] MV3 插件骨架、Side Panel、Content Script 和消息通道。
- [ ] Web Worker 中加载 Qwen3-0.6B ONNX，支持 WebGPU；失败时由应用显式切换到 WASM 兼容模式。
- [ ] 首次模型下载进度、取消、失败重试和缓存状态。
- [ ] 当前网页正文提取、摘要和问答，支持流式输出与取消生成。
- [ ] 划词工具条：解释、总结、改写、翻译。
- [ ] 加载态、空态、错误态、离线态和不支持页面提示。
- [ ] 最小权限、基础隐私说明、清除本地数据入口。

### P1 / v0.2 —— 产品能力闭环

- [ ] 一键起草：生成草稿、预览、用户确认后写入，永不自动提交。
- [ ] 本地 RAG：PDF / 当前网页入库、分块、Embedding、IndexedDB、带出处问答。
- [ ] OCR：可视区域截图或本地图片取字；模型以阶段验证结果为准。
- [ ] 当前标签页会话历史和上下文管理。
- [ ] 模型、文档、会话的存储用量与删除管理。

v0.2 允许分阶段交付：先交付 **v0.2a（本地 RAG）**，再在浏览器端 OCR 模型通过中英文实测后交付 **v0.2b（OCR）**。OCR 不与 RAG 绑定为同一阶段的强制交付项。

### P2 / v1.0 —— 上架与加分项

- [ ] 完整键盘操作、无障碍检查和中英文 UI 文案。
- [ ] 0.6B / 1.7B 模型切换，但只在目标设备实测通过后开放。
- [ ] 会话导出、多标签会话管理。
- [ ] 轻量向量索引；只有线性检索超过性能预算后才引入。
- [ ] Chrome Web Store 素材、隐私政策、权限说明和发布检查。

> 范围原则：任何 P1/P2 功能不得以牺牲 P0 稳定性为代价。若时间不足，优先交付完整的 v0.1，而不是五条功能线的半成品。

## 4. 功能需求与验收标准

### F-01 首次初始化与模型管理

#### 正常流程

1. 首次打开时先检测浏览器版本、WebGPU 可用性和存储空间。
2. 展示模型名称、预计下载体积、数据来源及“开始下载”按钮；未经用户确认不下载大模型。
3. 下载期间展示文件级或总进度、已下载大小、速度和取消入口。
4. 下载完成后执行一次最小推理自检，再进入可用状态。
5. 模型缓存存在且版本匹配时直接本地加载，不重复下载。

#### 异常与边界

- 网络中断：保留可复用缓存；若底层不支持断点续传，明确提示重新下载范围。
- 存储不足：下载前尽可能预检，失败后提供“清理模型/文档数据”入口。
- WebGPU 初始化或推理失败：释放相关资源，询问用户是否进入 WASM 兼容模式。
- 缓存被浏览器清理：回到初始化页，不出现无限加载。
- 模型 revision 或量化格式变化：旧缓存失效前先提示用户。

#### 验收标准

- 首次下载、缓存命中、离线启动、下载失败、存储不足五条路径均有可理解的界面状态。
- 第二次启动在离线状态下不请求模型网络资源并可完成一次摘要。
- 用户可单独删除模型缓存，也可一键清除 Wisp 全部本地数据。

### F-02 网页正文提取、总结与问答

#### 前置条件

- 用户已在当前标签页主动打开或启用 Wisp。
- 当前页面允许扩展注入，且存在可读 DOM 文本。

#### 正常流程

1. Content Script 提取标题、URL、正文和必要的结构信息，过滤导航、广告、脚本、样式和重复区域。
2. Side Panel 显示已识别页面标题和文本规模。
3. 用户选择快捷指令或输入问题。
4. 超出模型上下文的正文按确定性规则截断或分段；界面必须提示“仅分析了部分内容”。
5. Web Worker 流式返回结果；用户可停止生成、复制或重新生成。

#### 异常与边界

- 空页或正文过短：提示用户选择文字或换一个页面。
- 页面导航、刷新或标签页切换：终止旧页面任务或明确标记结果来自旧页面。
- 页面内容更新：用户可手动“重新读取页面”。
- 网页中的指令性文本一律作为资料而非系统指令处理。
- 模型无法回答时允许返回“不确定”或“当前页面未提供足够信息”。

#### 验收标准

- 在固定的 10 个普通文章页和 5 个 SPA 页面中，至少 80% 能提取主要正文，且不包含明显导航菜单堆叠。
- 受限页面、空页面和超长页面均有专用提示。
- 生成过程中点击停止后，500ms 内停止新增文字，1 秒内结束或中止当前任务。
- 切换标签页后不得把旧标签页正文误当作新标签页上下文。

### F-03 划词即时操作

#### 正常流程

1. 用户在已启用 Wisp 的页面选择 2～4000 个字符。
2. 在选区附近显示 Shadow DOM 工具条，包含解释、总结、改写和翻译。
3. 点击操作后打开或聚焦 Side Panel，并显示原选区、任务类型和流式结果。
4. 翻译默认根据选区语言在中文和英文之间切换，用户可在结果页修改目标语言。

#### 边界

- 密码、验证码、支付字段和被标记为敏感的输入区域不显示工具条。
- 选区位于跨域 iframe 时不保证支持。
- 页面滚动、缩放或选区消失后，工具条自动隐藏。
- 同一页面同时只保留一个划词工具条和一个活跃任务。

#### 验收标准

- 支持鼠标选择和键盘选择后的操作。
- 工具条不得改变宿主页面布局，且样式不受宿主 CSS 影响。
- 从操作点击到 Side Panel 显示任务状态，在目标设备上不超过 500ms。

### F-04 一键起草与确认填入

#### 正常流程

1. 用户聚焦支持的输入框后，通过 Content Script 按钮或 Side Panel 发起“起草”。
2. Wisp 只读取完成该功能所需的可见页面上下文和用户补充要求。
3. 草稿先在 Side Panel 中预览；用户可编辑、重新生成、复制或确认填入。
4. 只有点击“填入”后才写入原输入框；写入后由用户自行发送。

#### 支持范围

- v0.2 必须支持普通 `textarea`、文本型 `input` 和基础 `contenteditable`。
- 对 React/Vue 等受控输入组件，需触发必要的原生输入事件；无法可靠写入时退化为复制草稿。
- 不支持跨域 iframe 中的输入框和无法识别的复杂编辑器，并提供复制按钮。

#### 安全限制与验收

- 永不读取或写入密码、验证码、支付、银行卡和身份认证字段。
- 永不自动点击发送、提交、发布、确认或购买按钮。
- 未经用户点击确认，页面输入框内容不得发生变化。
- 固定测试集合中，普通输入框和基础 `contenteditable` 的填入成功率达到 90%。

### F-05 本地 RAG

#### 输入范围

- v0.2 支持文本型 PDF 和用户主动保存的当前网页正文。
- 默认限制：单个 PDF 不超过 20MB / 200 页，最多 20 个文档；实施时可根据实测调整。
- 扫描型 PDF 不直接视为文本 PDF，可引导用户进入 OCR 流程。

#### 处理流程

1. 解析文档并显示页数、字符数和解析状态。
2. 按 token 数进行分块，记录文档 ID、页码、块序号和原文片段。
3. 使用经中英文检索基准验证的 ONNX Embedding 模型生成向量。
4. 向量和元数据写入 IndexedDB；小规模数据先使用内存余弦相似度检索。
5. 回答显示文件名、页码和可展开的原文片段。

#### 数据管理

- 支持查看、重命名、删除单篇文档和清空全部知识库。
- 重复导入同一文件时提示覆盖或保留副本。
- 文档解析、分块和索引均支持取消；中途失败不得留下可查询的半成品索引。
- Embedding 模型或分块策略升级后，将旧索引标记为待重建。

#### 验收标准

- 构建不少于 5 份中英文测试文档和 20 个带标准出处的问题。
- 正确出处进入 top-3 的比例不低于 80%。
- 回答引用必须能定位到真实文件、页码和原文；找不到证据时明确说明“未在已导入资料中找到”。
- 1000 个文本块的 top-k 线性检索在目标设备上不超过 300ms；超过预算后才评估 HNSW 等索引。

### F-06 OCR 取字

#### 输入范围

- 可视区域截图，或用户主动选择的 PNG/JPEG 图片。
- v0.2 以中英文印刷体为目标，不承诺手写体和复杂表格还原。
- 截图必须由用户手势触发，不进行后台定时截图。

#### 输出与验收

- 输出可编辑的纯文本，并提供复制、继续提问和加入知识库入口。
- 明确展示识别语言、耗时和失败重试。
- 在固定的中英文印刷体测试集中，以字符准确率或人工核对准确率作为模型选型依据；首个可发布版本目标不低于 90%。
- OCR 模型在阶段验证前不写死。OvisOCR2 仅作为实验候选，不承担 v0.2 的交付承诺。

### F-07 会话、设置与状态

- v0.1 会话按 `tabId + 页面 URL` 关联；页面导航后保留旧会话但明确标注来源。
- v0.2 支持当前标签页多轮上下文，可由用户手动开始新会话。
- 关闭标签页后是否保留会话由设置决定，默认本地保留 7 天；用户可改为“不保留”。
- 设置包含模型状态、运行后端、输出长度、数据用量和清除数据。
- 隐身模式默认禁用持久化；若用户允许扩展进入隐身模式，仅在该隐身会话内保存临时数据。

## 5. 系统架构

```text
┌──────────────────── Chrome Extension（MV3）────────────────────┐
│                                                               │
│  Content Script              Side Panel（独立扩展页面）        │
│  ├─ 读取页面 DOM             ├─ React + TypeScript UI         │
│  ├─ 抓正文/选区/目标输入框   ├─ 流式结果、会话与状态           │
│  ├─ Shadow DOM 划词工具条    └─ 创建 Dedicated Web Worker      │
│  └─ 用户确认后填入                     │                      │
│          │                              ▼                      │
│          └──── chrome.runtime ── Web Worker（本地推理）        │
│                                  ├─ LLM：WebGPU / WASM         │
│  Service Worker                  ├─ Embedding（P1）             │
│  ├─ 浏览器事件与消息路由         └─ OCR（P1）                   │
│  ├─ Side Panel 唤起                                        │
│  └─ 权限与生命周期协调      IndexedDB：会话/文档/向量/元数据   │
│                             Cache API：模型权重与运行时缓存    │
└───────────────────────────────────────────────────────────────┘
```

### 架构约束

- Side Panel 是独立扩展页面，不使用 Shadow DOM 隔离宿主样式。
- 只有注入网页的划词工具条和起草入口使用 Shadow DOM。
- MV3 Service Worker 生命周期不稳定，不承担长时间推理和模型常驻。
- 推理放入 Dedicated Web Worker，避免生成过程阻塞 UI；正文提取本身也要分段处理，避免主线程长任务。
- Side Panel 关闭后允许释放模型内存；再次打开从缓存加载。是否保留 Worker 由阶段一实测决定。
- 所有 JS 和 WASM 运行时代码随扩展打包；远程只下载模型权重、tokenizer/config 等数据文件。
- 不建设 Python/FastAPI、业务 API、服务端数据库或账户系统；构建产物作为 MV3 扩展直接在浏览器中运行。

## 6. 技术选型

### 6.1 扩展与前端

- Chrome Extension Manifest V3。
- Chrome / Edge 最低版本暂定 116，以支持用户手势触发的 `sidePanel.open()`；发布前按实际 API 重新核定。
- UI 锁定为 React + TypeScript，使用 Vite 构建 MV3 扩展页面；不使用 Svelte，也不为当前纯浏览器扩展引入 Next.js 或 SSR。
- `@huggingface/transformers` 使用稳定 3.x，并在 lockfile 中固定具体版本。本文修订时官方稳定文档版本为 3.8.1；不得直接依赖 `main` 或未发布的 v4。
- ONNX Runtime Web 随依赖打包；扩展 CSP 加入运行 WASM 所需的 `'wasm-unsafe-eval'`，不放开 `'unsafe-eval'`。
- PDF 解析库、Markdown 渲染库等必须通过 MV3 远程代码检查，不得运行远程 JS/WASM。

### 6.2 模型

| 角色 | 当前方案 | 决策状态 | 说明 |
|---|---|---|---|
| LLM | `onnx-community/Qwen3-0.6B-ONNX`，WebGPU 使用 `q4f16` | 阶段一验证 | 官方模型仓库提供 Transformers.js WebGPU 示例 |
| LLM 兼容模式 | 同模型的 WASM 可用量化格式 | 待实测 | 必须显式重载，不承诺自动回退；可限制上下文与输出长度 |
| Embedding | 中英文 ONNX 候选模型 | P1 验证后锁定 | `all-MiniLM-L6-v2` 仅作为英文基线，不作为中英文产品默认模型 |
| OCR | 已有可用 ONNX 的中英文 OCR 候选 | P1 验证后锁定 | OvisOCR2 仅为实验候选，不阻塞交付 |

### 6.3 模型选型规则

- 不只比较参数量，还要比较模型体积、峰值内存、TTFT、tokens/s、中文质量、英文质量和浏览器兼容性。
- 每个模型固定仓库 revision、量化文件和许可证；升级模型时重新执行基准与回归测试。
- 不假设所有 WebGPU 设备都支持 `q4f16`；初始化失败必须进入可理解的错误或兼容路径。
- Embedding 前缀遵循所选模型卡，不泛化为所有 BGE 模型都使用 `query:` / `passage:`。

## 7. 数据与缓存生命周期

| 数据 | 默认位置 | 默认保留 | 用户控制 |
|---|---|---|---|
| 模型权重和 tokenizer/config | Cache API | 直到用户清除、版本失效或浏览器驱逐 | 删除单个模型 / 清除全部 |
| 会话与设置 | IndexedDB / `chrome.storage.local` | 会话默认 7 天，设置长期保留 | 新会话、删除会话、关闭历史 |
| PDF 原文、文本块、向量 | IndexedDB | 用户删除前 | 删除单篇 / 清空知识库 |
| 临时网页正文和选区 | 内存 | 任务或标签页生命周期 | 停止任务 / 新会话 |
| 截图与 OCR 临时图像 | 内存 | OCR 完成或取消后立即释放 | 不默认持久化原图 |

补充要求：

- IndexedDB 必须有 schema 版本和迁移策略。
- 启动时使用浏览器存储估算能力显示大致用量；不能可靠预测时明确说明。
- 浏览器可能驱逐 Cache API / IndexedDB 数据，产品必须能识别并重新初始化。
- 本地数据不默认做应用层加密，不宣称能防止同一操作系统账户中的其他本地访问；隐私说明中需如实披露。
- “清除全部数据”完成后再次检查各存储区，界面显示实际清理结果。

## 8. 权限、隐私与安全

### 8.1 权限策略

首版优先采用用户手势和最小权限：

| 权限 | 用途 | 策略 |
|---|---|---|
| `sidePanel` | 显示主界面 | 必需 |
| `activeTab` | 用户主动调用后读取当前页面 | 必需，代替默认全站常驻访问 |
| `scripting` | 在已授权当前页注入读取与交互脚本 | 必需 |
| `storage` | 保存设置和轻量状态 | 必需 |
| 截图相关能力 | OCR 当前可视区域 | 仅在用户触发 OCR 时使用 |

- v0.1 不默认申请 `<all_urls>`。如果后续为了永久划词入口需要广泛 host permission，必须先更新 PRD、隐私披露和安装体验评估。
- 商店页面和扩展“关于”页列出每项权限及原因。

### 8.2 隐私承诺

除用户主动触发的模型文件下载外，Wisp 不向开发者或第三方服务器上传网页内容、URL、文档、图片、表单内容、提示词、回答或使用数据。无账户、无遥测、无广告 SDK、无远程错误日志。

“数据不上传”不等同于“浏览器完全没有网络请求”：扩展安装与更新、浏览器自身服务和模型首次下载可能产生网络活动。Demo 只验证 Wisp 核心业务在模型缓存后不发起远程请求。

即使只在本地处理，仍需在隐私政策和 Chrome Web Store Data Usage 中披露读取网页、截图、表单和本地文档的用途、保存期限和删除方式。

### 8.3 安全要求

- 网页正文、PDF、OCR 文本均视为不可信数据，并与系统指令明确分隔。
- 页面中的文字不能触发点击、填表、下载、权限申请或任何自动操作。
- 模型输出经安全 Markdown 渲染；禁用原始 HTML或进行严格白名单清理；过滤 `javascript:` 等危险链接。
- 新窗口链接使用安全的 `rel` 属性；不执行模型生成的代码。
- 不读取密码、支付、验证码、隐藏认证字段和浏览器 Cookie。
- 写入输入框必须绑定用户当前明确选中的目标，页面导航或目标失效后要求重新确认。
- 所有 JS/WASM 代码本地打包，禁止远程托管代码；模型文件作为数据下载并固定来源与 revision。
- 发布前执行依赖许可证、CSP、权限和远程代码扫描。

## 9. 非功能需求与暂定性能预算

以下目标以“目标测试设备”上的 Release 构建为准。阶段一完成后用真实数据修订，不得只选择最好结果。

### 9.1 目标设备

在阶段一开始前记录至少两台设备：

1. 推荐设备：具体 CPU、集显、RAM、操作系统、浏览器和驱动版本。
2. 兼容设备：无可用 WebGPU 或 WebGPU 初始化失败，使用 WASM。

不再把“≥2GB 可用 GPU 内存”作为无法可靠检测的硬门槛；改用真实设备与 `GPUAdapter` 能力测试。

### 9.2 性能目标

| 指标 | v0.1 暂定目标 |
|---|---|
| 缓存后模型可用时间 | 推荐设备 P50 ≤ 10 秒，P95 ≤ 20 秒 |
| TTFT | 1000 个中文字符上下文下 P50 ≤ 4 秒 |
| 生成速度 | 推荐设备 ≥ 5 tokens/s |
| 划词工具条出现 | 选区稳定后 ≤ 150ms |
| 停止生成 | 500ms 内停止新增文字，1 秒内结束任务 |
| 主线程响应 | 生成期间无持续 100ms 以上的明显长任务 |
| 向量检索 | 1000 chunks、top-k ≤ 300ms |
| 稳定性 | 固定完整 Demo 连续运行 10 次无崩溃 |

### 9.3 体验与可访问性

- 每个异步功能都有加载、成功、空、失败、取消和重试状态。
- 所有核心按钮有文本或可访问名称，焦点样式清晰，支持键盘操作。
- 尊重 `prefers-reduced-motion`，不使用影响阅读的装饰性动画。
- 不用原始“Thinking / 思维链”作为 P0 功能；只展示“读取页面、加载模型、生成回答”等可靠过程状态。
- 如需展示模型原始推理内容，仅作为 P2 实验选项，默认关闭，并明确其不等于可靠解释。

## 10. 异常状态矩阵

| 场景 | 产品行为 |
|---|---|
| 页面禁止注入 | 说明浏览器限制，禁用页面相关操作 |
| 页面没有正文 | 建议划词或切换页面 |
| 页面过长 | 提示只分析部分内容，并显示处理范围 |
| WebGPU 不可用 | 提供 WASM 兼容模式及速度提示 |
| WebGPU 推理中崩溃 | 释放任务，保留用户问题，允许重试或切换兼容模式 |
| 首次下载失败 | 显示失败文件、原因和重试入口 |
| 缓存缺失或损坏 | 清理对应版本缓存并重新初始化 |
| 离线且模型未缓存 | 说明需联网完成首次下载 |
| 存储不足 | 展示用量并提供清理入口 |
| 标签页切换/关闭 | 取消或冻结旧任务，防止上下文串页 |
| PDF 解析失败 | 说明可能是扫描件、加密或格式不支持，建议 OCR |
| OCR 无法识别 | 允许重新截图、换图或手动复制 |
| 输入框写入失败 | 保留草稿并提供复制按钮 |

## 12. 关键风险与应对

| 风险 | 影响 | 应对与退出条件 |
|---|---|---|
| 集显 WebGPU 内存或算子兼容问题 | 核心推理不可用 | 阶段一先做 0.6B q4f16 真机验证；失败则评估更小模型或缩短上下文 |
| WASM 模式速度不可接受 | “兼容模式”名存实亡 | 单独记录 TTFT/tokens/s；低于可用阈值则只提供明确的不支持提示，不虚假承诺回退 |
| 0.6B 输出质量不足 | 摘要和问答失真 | 收敛场景、固定提示模板、限制上下文，并建立小型质量回归集 |
| 中英文 Embedding 选型错误 | RAG 检索不稳定 | 用固定双语测试集选择模型，不根据参数量拍板 |
| OCR ONNX 转换失败 | OCR 延期 | 只选已在浏览器验证的模型；OvisOCR2 不作为交付依赖 |
| 首次下载慢或缓存被清理 | 新用户流失 | 用户确认、明确体积、进度、重试、缓存诊断和重新下载 |
| 网页提示注入 | 回答偏离或诱导操作 | 网页仅作不可信上下文；不向模型暴露自动操作工具 |
| 权限过宽导致商店拒审 | 无法上架 | v0.1 使用 activeTab；权限逐项说明并执行最小权限检查 |
| 功能太多稀释完成度 | 项目长期无法交付 | P0 冻结后再开始 P1；时间不足直接砍 P1/P2 |

## 16. 技术决策与面试叙事

### 已确定的决策

- 放弃浏览器中不可行的 27B GGUF 路线，选择有 Transformers.js ONNX 权重的 0.6B 模型。
- 推理不放在 UI 主线程，也不依赖生命周期短的 MV3 Service Worker。
- 小规模 RAG 先用 IndexedDB + 内存余弦检索，只有实测超预算才引入 WASM 向量索引。
- 起草只做到“生成—预览—用户确认—填入”，不做自动发送和多步网页代理。
- 不把未经验证的 OvisOCR2 转换作为产品交付依赖。

### README 应记录的真实数据

- 目标测试设备与浏览器/驱动版本。
- q4f16 与其他可用量化格式的体积、加载时间、峰值内存和质量对比。
- 首次下载与缓存启动时间、TTFT、tokens/s。
- WebGPU 失败原因和 WASM 兼容模式实测结果。
- 网页提取、RAG 和 OCR 的固定测试集与失败样例。
- MV3 CSP、远程代码、缓存和最小权限问题的解决过程。

### 简历描述模板

> **Wisp —— 浏览器端离线 AI 副驾驶（Chrome 扩展 · 个人项目）**  
> 基于 Manifest V3、WebGPU、Web Worker 与 Transformers.js，在浏览器本地运行量化小模型，实现网页摘要、划词处理、安全起草、本地文档检索和 OCR；除模型下载外不上传用户内容，无后端和 API 成本。通过模型量化、缓存、任务取消与主线程隔离，在指定集显设备上实现首 token 延迟 __ 秒、生成速度 __ tokens/s，并以固定测试集验证正文提取、检索出处和 OCR 准确率。

所有空白数字必须在 Release 构建实测后填写。
