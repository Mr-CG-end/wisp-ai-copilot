## A. 划词交付（F-03 主链路）

| # | 操作 | 预期 |
|---|---|---|
| A1 ★ | **面板关闭**时，在已启用页面划词点「解释」 | 三选一，记录是哪种：**(A)** 面板自动弹开并在 500ms 内出现「01 解释 · 生成中…」；**(B)** 面板没弹开，页面就地提示「点击工具栏扩展图标继续」，手动点图标后**立刻**继续那次解释；**(C)** 无反应——需要 SW console 里 `sidePanel.open` 的报错原文。**若为 (B)，请贴出 rejection 消息**，那句话决定「手势能否跨 CS→SW」的最终结论，直接对应设计文档 §10 仅存的三处未决之一 |
| A2 | 面板已打开时划词点「总结」 | 500ms 内出现新一轮，走广播路径 |
| A3 ★ | 重复 A1（面板从关闭态弹开） | 轨迹上只有 **1** 轮。两条投递路径会同时命中，看到两轮内容相同即为去重失效 |
| A4 | 新开面板、**不点**「读取当前页」，直接划词 | 顶部一行「本轮来自划词选区，未读取整页」+「读取当前页」按钮，下方正常渲染结果；底部**没有**追问框 |
| A5 | 重载扩展，在模型下载/加载中划词 | 初始化页上方出现「模型尚未就绪 / 完成初始化后将继续这次划词操作」；就绪后自动执行**一次**。超过 30s 才就绪会因 TTL 过期丢弃，属设计内行为，请记录实际就绪耗时 |
| A6 ★ | 生成摘要吐出几行后立即划词点「解释」 | 不弹确认框；摘要变「已停止」轮次且**半截内容留在纸面上**，划词结果追加为新一轮。摘要整轮消失即为归档规则回归 |
| A7 | 同一段中文选区依次跑四个动作 | 编号 01–04 连续，标签正确；改写与翻译的输出明显长于解释与总结，不在半句话处硬截 |
| A8 | 纯中文选区点翻译；纯英文选区点翻译 | 中→英、英→中；DEV console 里送进模型的是 `目标语言：English` / `目标语言：中文`，**不是** `en` / `zh` |
| A9 | 在翻译轮的工具行下拉里改目标语言 | 原地重跑（编号不变、不新增一节），总轮数不变；生成中下拉与「重新生成」不可点 |
| A10 ★ | 晾置 ≥30–60s 或手动 stop 掉 SW，关闭面板后再划词 | 同 A1。epoch 从 `chrome.storage.session` 恢复，不应出现「页面已导航或关闭」 |
| A11 | 划词生成完成后切到另一标签页 | 出现跨标签横幅；划词轮次仍在，「重新生成」变灰 |
| A12 ★ | 划词生成中按 F5 刷新原页面 | 该轮立刻停止并转错误态，已生成部分保留。**继续吐字即说明 `adoptCtx` 没写进 `boundCtxRef`** |
| A13 | SPA 站点选中文字 → 点进另一文件 → 再点工具条动作（选做） | 面板打开但不产生轮次（SW 侧 URL 比对丢弃）。B10 落地后通常触发不到，属兜底 |
| A14 | 隐身窗口划词跑一次 | 结果正常，IndexedDB 不落 session/message |

## B. 划词工具条（Shadow DOM）

| # | 操作 | 预期 |
|---|---|---|
| B1 ★ | **先点工具栏 Wisp 图标启用**，再拖选一段话松手 | 约 150ms 内工具条出现在选区正下方 6px、水平居中，四个文字按钮。**不点图标直接划词不出工具条是预期行为**（CS 按需注入、不跨刷新存活） |
| B2 | 点一下正文，Shift + 方向键扩选 | 同样出工具条；连续按方向键不闪烁 |
| B3 | Esc | 立即消失，再按无异常 |
| B4 | Tab 进工具条后连按四次；再 Shift+Tab | 焦点在四按钮间循环不跑回页面，2px 蓝色内描边；此时选区仍在、工具条不消失 |
| B5 | 滚轮滚动 / Ctrl +- 缩放 / 页内滚动容器里滚动 | 三种都立刻消失，不跟随不残留 |
| B6 ★ | 划词前后各截全页图对比，并看 `document.body.scrollHeight` | 布局零跳动、滚动高度不变、不出现新滚动条 |
| B7 | 在自带 `button{}` 全局样式的站点（GitHub / Bootstrap 站）划词 | 外观与 B1 完全一致，不继承宿主圆角/底色/字体 |
| B8 ★ | 在 `body{position:relative}` 的站点（多数 WordPress 主题）**滚到页面中部**再划词 | 工具条紧贴选区，**不掉到页面底部**。这条专验 `fixed` + 视口坐标的选择 |
| B9 | 祖先带 `transform`/`filter`/`contain` 的页面（或 DevTools 里给 body 加 `transform: translateZ(0)`） | **已知失效场景**：落点会整体偏移。请回报偏移量级与站点，决定要不要加降级分支 |
| B10 | SPA 站点选中文字让工具条出现，不点按钮，直接点站内链接跳转 | 跳转瞬间消失，跳转后不复现 |
| B11 | 密码框内选中已输入字符；再从旁边说明文字拖选到密码框里 | 两种都不出工具条 |
| B12 | 普通 `<input type="text">` 内选中文字 | 不出工具条（产品口径：会和输入法候选框抢位置） |
| B13 | 选中单个字符；Ctrl+A 全选超 4000 字长文 | 两种都不出 |
| B14 | 反复选择/取消 20 次后在 Elements 里搜 `wisp-selection-toolbar` | 始终只有 1 个宿主元素 |
| B15 | 点「解释」 | 原位变「正在解释…」+ 1px 苔绿线向右生长，约 1.5s 后消失；面板打开并出现该任务。开启「减少动态效果」后重复：文字照常，线直接是终态 |
| B16 | 深色网页 / 系统深色主题下划词 | 工具条仍是浅色纸面（§5.10 明确不做背景自适应） |
| B17 | 在一个新标签页点 Wisp 图标，用 Performance 面板量「点击 → 工具条可用」的耗时 | 记录数值。工具条引入 React 后 content script 从 40.6 kB 涨到 198.5 kB（gzip 64.6 kB），这段解析落在**每次注入**上（CS 不跨刷新存活）。若明显拖慢启用动作，退路已明确且有界：工具条只有四个按钮两个状态、不依赖 React 的任何调度能力，改手写 DOM 即可压回 ~45 kB。**没有实测数字之前不要改**——两条阶段门时延指标（工具条 ≤150ms、点击到状态 ≤500ms）都在注入之后计时，不受这段影响 |

## E. 尚未落地、需要你提供的

- **扩展图标**：`wxt.config.ts` 无 `icons`、无 `action.default_icon`，工具栏显示浏览器默认拼图。PNG 资产 agent 生成不了。四档尺寸 16/32/48/128，建议暖象牙圆角方底 + 苔绿 W 或一条微光轨迹曲线。在此之前，手势退路文案写的是「点击浏览器工具栏上的扩展图标」，不依赖图标识别度。
- **W2 欠下的三处样式**：`.wisp-turn-selection`（划词来源回显，需 3 行截断，否则 4000 字选区会把结果顶出视口）、`.wisp-turn-lang`（翻译目标语言下拉，要与小按钮等高同字号）、`.wisp-selection-only`（无快照时替代凭证行的说明行）。这三处目前是**无样式裸元素**，能用但不好看，排在 W3 一并补。
