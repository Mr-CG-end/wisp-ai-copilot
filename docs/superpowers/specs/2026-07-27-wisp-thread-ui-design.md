# Wisp UI 设计：轨迹（The Thread）

> 日期：2026-07-27
> 状态：已评审，待转实现计划
> 范围：Side Panel 全部界面 + 划词工具条（M3 Task 11）
> 继承：`docs/ui/Wisp_M2_UISpec.md` 的视觉语言；本设计定稿后应升为 UISpec v3

## 1. 目标与判定标准

让 Wisp 从「功能正确的扩展」变成「有辨识度的作品」，**但以好用优先**——冲突时向可用性倾斜。

判定标准，三条同时成立才算达成：

1. 签名元素必须**先有功能价值**。任何纯装饰的视觉主张不算数。
2. 面板与划词工具条共享同一套语汇，用户在两个表面上认得出是同一个产品。
3. 不牺牲已有的产品语义与无障碍要求。

## 2. 出发点：一个被浪费的元素和一个没有分量的内核

**被浪费的元素**：现有设计里那条苔绿曲线（微光轨迹）从 favicon 垂到「01 摘要」就结束了。它长得像承载信息，实际不承载任何信息。

**没有分量的内核**：Wisp 在概念上最独特的地方是**快照**——它读一次网页，之后所有回答都基于那一刻的冻结副本，不再观察 DOM。这既是隐私承诺也是产品行为，但目前只被一行小字表达（「已读取前 3,000 字」）。

本设计把前者升级为信息骨架，把后者提升为有分量的视觉对象，两者合为一条线。

## 3. 继承与不可动的约束

**继承**（不重新发明）：暖象牙背景 `#F2EFE7`、纸面 `#FBFAF6`、单一苔绿强调色 `#476C5A`、编辑器/纸张隐喻、系统字体、4px 基础网格。

**不可动的产品语义**：

- 来源标识常驻
- 快照语义：界面不得暗示持续监视网页
- 每个异步功能覆盖六态（idle / loading / success / empty / error / cancelled）
- 除模型下载外不出网——包括**不为取真实 favicon 发起网络请求**
- WebGPU 失败不自动切 WASM

**明确不做**：底部导航；M2 阶段提前放出设置与历史入口；纸张纹理（属作品集展示图，产品 UI 不做）；第二个强调色；渐变、玻璃拟态、装饰性动画。

## 4. 核心概念：轨迹

一条 1px 苔绿竖线，从快照凭证出发，向下贯穿整个滚动区，每一轮任务在线上留下一个节点。它从「结果卡片内部的一列」提升为**页面级的一条轨道**。

```
┌────────────────────────────────────┐
│  Wisp              本地·WebGPU·省资源 │  44px 顶栏
├────────────────────────────────────┤
│ ▣ │ web.dev · 3 分钟前读取           │  ← 快照凭证（轨迹起点，sticky）
│ │ │ 理解 WebGPU：浏览器端推理的关键路径 │
│ │ │ 3,842 字 · 已读取前 1,400 字      │
│ │ │                        重新读取   │
│ │ │                                  │
│ │ │ [生成摘要]                        │
│ ● │ ┌────────────────────────────┐   │
│01 │ │  纸面 · 摘要输出              │   │
│摘要│ │                            │   │
│ │ │ └────────────────────────────┘   │
│ ● │ ┌────────────────────────────┐   │
│02 │ │  纸面 · 追问输出              │   │
│追问│ │                            │   │
│ ╎ │ └────────────────────────────┘   │  ╎ 断口 = 该轮被停止
│ ╎ │                                  │
├────────────────────────────────────┤
│  基于这份快照提问…                 ▷ │  底部提问栏
└────────────────────────────────────┘
```

纸面保留：模型输出仍是页面里唯一形成明显容器的区域。轨道在纸面**之外**并行向下，两者不争。

### 4.1 轨迹线即分隔线

现状有两条竖线——边注栏右侧的分隔边框，和那条装饰曲线，冗余。新方案只有一条：**轨迹线即边注栏与内容的分隔线**，节点骑在线上，编号与标签在线的左侧。

**线不是一整条，而是每一轮自己画一段**，视觉上接成连续线。这样每段可独立为实线／虚线／暖红，状态逐段不同天然成立，也不必处理跨 DOM 块画线。

### 4.2 六态收敛到轨迹上

本表只描述**单轮任务**的六态。跨标签是面板级状态，不属于此表，见 §4.3。

| 状态 | 节点 | 线段 |
|---|---|---|
| 生成中 | 空心圆，**实线描边** | 从上一节点向下生长 |
| 成功 | 实心圆 | 实线 |
| 空结果 | 空心圆，**虚线描边** | 实线 |
| 已停止 | 实心圆带横杠 | 节点后留 4px 断口，续为虚线 |
| 出错 | 暖红实心圆 | 该段转暖红 |

「生成中」与「空结果」都是空心圆，靠描边虚实区分——生长中的线段是前者的即时线索，但它会结束，所以静态形态本身必须可区分。两者的文字标签也不同（`生成中…` / `没有返回内容`）。

顺带解决审查报告 U-16：被中断的半截回答此前与完整回答外观完全相同，现在从轨迹上一眼可辨。

**无障碍红线**：轨迹永远不是唯一的状态载体。节点旁的文字标签同时写明状态（`02 追问 · 已停止`）。形状与颜色只用于加速识别。

### 4.3 快照凭证

轨迹的起点，把「快照」从一行小字提升为有分量的视觉对象：

- 30px 方形、7px 圆角，内含**域名首字母**（不发网络请求取真实 favicon，守权限红线）
- 下方微文本给读取时刻：`刚刚` / `3 分钟前`

**快照过期与跨标签是两回事，视觉必须区分**——这是用户最容易误解的地方：

| 情况 | 含义 | 表现 |
|---|---|---|
| 绑定页导航／刷新 | 快照**已失效**，与页面不再对应 | 凭证边框转虚线、文本变 `快照已过期`、轨道起点出现断口 |
| 用户切到别的标签页 | 快照**仍然有效**，只是当前不在那个标签 | 凭证与轨迹**不变**；顶部出现横幅「当前结果来自《…》，你正在看另一个标签页」+「改读当前页」 |

一枚凭证同时回答用户最易困惑的三件事：读的是哪一页、什么时候读的、现在还作不作数。

### 4.4 动效纪律

- 生长用 CSS `transform: scaleY()` + transition，**不用逐帧 JS**
- `prefers-reduced-motion` 下直接跳终态
- 节点不脉动、不发光、不呼吸
- 生成期间唯一在动的是一条 1px 线的末端，GPU 成本可忽略

最后一条与性能收口直接相关：宿主页面卡顿的根因是推理与浏览器合成器争抢同一块 GPU，任何面板侧的持续动画都会加剧它。

## 5. 面板布局

页面级两列栅格 `[轨道 44px][内容 1fr]`；顶栏与底部提问栏跨两列（属 chrome，不属线索）。

### 5.1 历史与当前轮同构

现状：历史是浮在结果区上方的分离块，有独立的 header 结构。

新结构：**每一轮都是一行 `[轨道单元][纸面]`**，历史轮次只是节点更靠上。

- 滚动查看历史时轨迹连续不断
- 渲染层收敛为单个 `Turn` 组件
- U-16 顺带解决：状态就在轨道上

### 5.2 只 sticky 快照凭证

收口计划 Task B 原方案是整条上下文栏 sticky，代价是顶部固定占用从 44px 增至 132px，矮窗口下比例偏高。

本设计改为**只 sticky 凭证本身**（30px 方块 + 域名行），标题与字数行随内容滚走。三点收益：

- 顶部固定占用降至约 **78px**（44 + 34）
- 轨迹起点始终可见，线从它继续向下，视觉成立（整条栏 sticky 会让线从一个浮着的东西垂下来）
- 「来源常驻」的产品语义满足——域名与凭证都在；标题属一次性信息，滚走无损失

**此项取代收口计划 Task B，Task B 应取消。**

### 5.3 两处冗余的裁撤

- **删掉每轮重复的来源标识**。轨道起点已有常驻凭证。仅在「该轮来源 ≠ 当前快照」时显示（如跨标签后保留的旧轮）——那才是真正需要区分的时候。
- **「生成摘要」首轮后降级为次按钮**。不消失（换性能档位后可能需重新摘要），但主操作让位给底部提问。

结果操作栏保留在纸面**顶部**工具行（审查报告 U-3 裁决）：停止按钮必须在长输出流式滚动时无需下拉即可点到。

### 5.4 初始化页共用同一套语汇

初始化本就是一条有序的链，轨迹在此的复用价值最高：

```
▣ 确认模型来源
●  下载权重 390 MB      ← 当前步，空心 + 生长中
○  加载到 WebGPU
○  自检一次生成
```

已完成节点实心，当前步空心且线在生长，失败节点转暖红并在此断线。

这让「首次需等待约 47 秒」变得可理解——用户看得见自己处在四步中的哪一步，而非盯着一个孤立的进度条。初始化页与工作区从此共享语汇。

## 6. 划词工具条

约束最硬的表面：宿主背景完全未知（白底、黑底、彩色、图片皆有可能）。

**方案：纸面 + 强化的物理浮起感。** 隐喻本身能成立——纸放在任何桌面上都还是纸。**不做背景自适应**，那会让苔绿在深色网页上消失，反而丢掉辨识度。

- 背景 `--wisp-surface`，1px 边框但比面板内深一档（对抗未知背景）
- 投影 `0 4px 16px rgba(0, 0, 0, 0.16)`，比面板内重——需明确脱离宿主
- 高度 34px，圆角 8px
- **左侧 3px 苔绿边条**：轨迹在宿主页面上的一次克制出场，无需指向性引线即可建立归属
- 四个动作用文字不用图标（图标要猜，文字不用）。「解释 总结 改写 翻译」加间距约 200px 宽

**点击后的反馈**：面板可能尚未打开，工具条必须自己给回执。该动作文字变为「正在解释…」，下方浮现一条 1px 苔绿线**向右生长**——轨迹的生长语汇，跨表面一致。约 1.5 秒后工具条消失，面板接管。

**无障碍**：四个按钮有可见文字，`role="toolbar"`，Esc 关闭。

## 7. 排版基础层

不引入衬线字体（中文衬线体积达数 MB，仅做拉丁子集会导致中英混排字形不一致）。用系统字体做严格的层级与节奏。

### 7.1 字号层级从七八档收敛到五档

现状散落 10 / 11 / 12 / 13 / 14 / 16 / 18 / 20 / 24px。收敛为：

| 值 | 用途 |
|---|---|
| 20px / 28 / 650 | 初始化页标题 |
| 15px / 22 / 600 | 区块标题 |
| 14px / 22 / 400 | 正文与模型输出 |
| 12px / 18 / 450 | 元信息 |
| 11px / 16 / 500 | 微文本（轨道标签、读取时刻） |

删除 10、13、16、24px。18px 品牌字标保留——它是字标，不进文字层级。

### 7.2 基线节奏

模型输出行高 22px，段间距 12px，标题上间距 20px、下 8px。长文有可预期的呼吸。

### 7.3 等宽数字全局启用

所有数字（字数、百分比、轨道编号、读取时刻）使用 `font-variant-numeric: tabular-nums`。流式更新时不左右跳动，轨道编号 `01`／`02` 尤其需要。

### 7.4 行宽：一个必须正视的代价

轨道占 44px，直接压缩正文行宽。实测推算（页面水平内边距 16px，纸面内边距 14px）：

| 面板宽度 | 轨道 | 文本行宽 | 约合中文字符 |
|---|---|---|---|
| 320px | 28px | 236px | 约 17 字 |
| 400px | 44px | 296px | 约 21 字 |
| 500px | 44px | 396px | 约 28 字 |

UISpec 规定上限约 52 字，因此**行长不是问题，问题是行偏短**，320px 档尤其紧。补偿两条：纸面内边距由 16px 收至 14px；≥420px 时轨道**不增宽**，多出宽度全部给内容。

320px 下约 17 字/行是最小宽度处的真实代价，判定为可接受但确实紧凑。

## 8. 响应式

| 宽度 | 轨道 | 内容 |
|---|---|---|
| 320px | 28px，只留编号；任务标签移至纸面工具行 | 水平内边距 14px |
| 360–419px | 44px，编号 + 标签 | 默认布局 |
| 420–500px | 固定 44px，不增宽 | 多出宽度全给内容 |

无横向滚动；长标题两行截断，完整标题经原生 `title` 或可访问名获得。

## 9. 无障碍

轨迹承载状态，因此既不能当纯装饰忽略，也不该要求读屏用户去理解一条线。

- 线段与节点 `aria-hidden="true"`，图形本身不进无障碍树
- **状态由文字承载**：每轮容器为 `<article>`，可访问名是完整版 `第 2 轮 · 追问 · 已停止`（视觉上只显示 `02 追问 · 已停止`）
- 播报范围收窄（审查报告 U-14）：`aria-live="polite"` 只挂状态行，**不挂正文容器**——流式每 60ms 触发一次读屏播报是实打实的可用性缺陷。生成完成时播报一次
- Tab 顺序 = 视觉顺序：顶栏 → 凭证行「重新读取」→ 命令区 → 各轮工具行 → 底部提问栏
- 焦点环 2px `--wisp-focus`，偏移 2px
- `--wisp-text-muted` 加深至约 `#5F675E` 以通过 WCAG AA（审查报告 U-13）
- `prefers-reduced-motion`：轨迹生长与工具条生长线全部跳终态
- 不仅用颜色表达状态

## 10. 实现边界与测试

### 10.1 新增单元

| 单元 | 职责 | 依赖 |
|---|---|---|
| `core/panel/thread.ts` | 把 store 的 `history` + `currentTask` + `streamBuffer` 投影成统一轮次数组。纯函数 | store 类型 |
| `components/Thread.tsx` | 轨道单元（节点 + 线段），按 status 决定形态。纯展示 | `thread.ts` 类型 |
| `components/Turn.tsx` | 一轮 = 轨道单元 + 纸面。历史与当前轮共用 | `Thread`、`StreamMarkdown` |
| `components/SnapshotStamp.tsx` | 快照凭证（首字母、读取时刻、过期态） | store 的 `page` |

`thread.ts` 是关键：把「三个 store 字段 → 轮次数组」抽成纯函数后，渲染层只剩摆放。**这也是唯一需要单测的新逻辑**，其余为纯展示与 CSS。

**本设计不新增 store 字段**——轮次是投影，不是状态。

### 10.2 改造

- `TaskPanel.tsx`：现有「历史块 + 结果区」双结构换成 `Turn` 列表
- `ModelSetup.tsx`：四步节点
- `style.css`：页面级栅格、字号层级收敛、轨道样式

### 10.3 测试

`core/panel/thread.test.ts`：

- 历史与当前轮共同投影为连续轮次数组，顺序正确
- 流式进行中的当前轮 status 为 `loading`
- 被停止／出错的历史轮次保留其终态，不被归一化为成功
- 空历史时只产出一轮
- 无当前任务时不产出空轮

## 11. 与收口计划的关系

`docs/Wisp_M2收口与设计文档回写计划.md` 的四个任务与本设计有重叠，必须理清先后，否则会实现一遍再推翻：

| 任务 | 处置 | 理由 |
|---|---|---|
| Task A 生成期负载收口 | **必须先做** | 本设计的动效纪律建立在「不用逐帧 JS」之上，Task A 正是删除逐帧打字机动画的前提 |
| Task B 来源标识常驻 | **取消** | 已被 §5.2 取代，效果更好且代价更小（顶部固定占用 78px vs 132px） |
| Task C 提取降级路径守卫 | 独立，随时插入 | 与 UI 无关 |
| Task D 设计文档契约回写 | 独立，随时插入 | 本设计不新增 store 字段，§3.3 回写内容不受影响 |

**执行顺序：Task A → 本设计 → Task C／D 任意插入。**

### UISpec 的处置

改动幅度超出「升版」，应作 **UISpec v3**，覆盖面板 + 划词工具条。

审查报告附录中 19 项裁决建议里，U-1（来源常驻）、U-3（操作栏位置）、U-4（边注栏宽度）、U-13（对比度）、U-14（aria-live 范围）、U-16（历史状态标记）已被本设计吸收；其余为纯令牌项，随 v3 一起落地。

## 12. 已评估并排除的方案

| 方案 | 排除理由 |
|---|---|
| 方向 B「纸样」：给模型输出用本地打包的衬线字体 | 中文衬线体积达数 MB；仅做拉丁子集会导致中英混排字形不一致，反而更糟。其排版严谨度已作为基础层吸收（§7） |
| 方向 C「仪表」：把本地推理做成精密仪表语言 | 与 UISpec 既定的「编辑感、轻盈」关键词正面冲突，且极易滑回阶段一已被明令删除的调试界面 |
| 工具条背景自适应宿主明暗 | 会让苔绿在深色网页上消失，辨识度归零。改用「纸放在任何桌面上都还是纸」的物理隐喻 |
| 划词时给选区加苔绿高亮 | 功能上更好（跨行选区范围一眼可见），但需覆盖宿主 `::selection` 渲染，有干扰用户的风险 |
| 工具条与选区之间画指向性引线 | 固定 8px 长度下几乎读不出「轨迹」意图；左侧 3px 边条以更低成本达成归属感 |
| 整条上下文栏 sticky | 顶部固定占用 132px 偏高，且会让轨迹起点浮在滚动内容上，线从浮动物垂下视觉不成立 |
